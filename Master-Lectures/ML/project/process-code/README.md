# Impact of Prompting Strategies on Information Extraction from AI News Articles Using Open-Source LLMs

Master's ML project. I compare **zero-shot**, **few-shot**, and **structured (JSON)**
prompting for extracting company names, AI model names, and AI technology labels
from AI-related news articles, using two open-source LLMs (**Llama 3.1 8B
Instruct** and **Gemma 3 12B IT**, via OpenRouter).

**Research question:** How do different prompting strategies affect information
extraction performance of open-source LLMs on AI-related news articles?

The full write-up — methodology, results, discussion, and conclusion — is in
`ml-project.ipynb`. This README is just a map of the repo.

## Pipeline

| # | Step | Script | Output |
|---|------|--------|--------|
| 1 | Data Collection | *(external: MIT AI News dataset)* | `MIT_AI_ARTICLES.csv` |
| 2 | Data Preparation & EDA | `ml-project.ipynb` (Part 1–2) | `clean_articles.csv`, `evaluation_articles.csv` |
| 3 | Ground Truth Construction | `ml-project.ipynb` (Part 3) + manual annotation | `annotation_sheet.csv`, `ground_truth_annotations.csv` |
| 4 | Prompt Design | `prompt_templates.py` | — |
| 5 | Model Inference | `run_inference.py` | `raw_extractions.csv` |
| 6 | Output Parsing | `parse_outputs.py` | `parsed_extractions.csv` |
| 7 | Performance Evaluation | `evaluate.py` | `evaluation_metrics.csv` |
| 8 | Error Analysis | `error_analysis.py` | `error_analysis.csv` |
| 9 | Final Report & Figures | `ml-project.ipynb` (Part 9) | `fig1`–`fig4_*.png` |

100 articles were manually annotated with ground-truth company, model, and
technology labels; those annotations are the reference for every metric in
this project. AI technology labels are restricted to five predefined
categories (Retrieval-Augmented Generation, Reinforcement Learning,
Generative AI, Multimodal AI, AI Agents); companies and model names are
open-set.

## Reproducing the results

```bash
pip install -r requirements.txt
```

Create a `.env` file in this folder with an [OpenRouter](https://openrouter.ai)
API key (this is the only step that costs money — the full run is ~600 API
calls, well under $1):

```
OPENROUTER_API_KEY=sk-or-...
```

Then, in order:

```bash
python run_inference.py      # Step 5 — resumable, skips already-completed calls
python parse_outputs.py      # Step 6
python evaluate.py           # Step 7
python error_analysis.py     # Step 8
```

Each script reads the previous step's CSV and writes its own; re-running any
of them regenerates that file deterministically from the one before it, so
none of the CSVs in this repo need to be treated as hand-edited source data
(the one exception is `ground_truth_annotations.csv`, which is the manually
annotated ground truth and is not regenerated by any script).

Finally, open `ml-project.ipynb` to see the full pipeline narrated step by
step, including the figures and the final discussion/conclusion.

## Key results (summary)

- **Few-shot prompting** gives the best overall F1 for both models
  (Llama 3: 0.51, Gemma 3: 0.49), ahead of zero-shot and structured.
- **Structured (JSON) prompting** did not improve extraction accuracy, but
  it made the output format far more reliable to parse.
- **AI model names** are the easiest entity type to extract (F1 up to 0.79);
  **companies** are the hardest (F1 ≤ 0.50) — largely because the dataset is
  MIT News, and "MIT" gets extracted as a company in 98/100 articles even
  though the ground truth (correctly) does not count MIT as an AI company
  in that context.
- Across every model/strategy combination, **recall is high but precision
  is low**: both models over-generate rather than miss entities. Error
  Analysis shows this is almost entirely driven by false positives, not
  category confusion (11 instances) or JSON formatting failures (3
  instances).
